\section*{Appendix B: Hyperparameter Settings}

All models were trained with consistent hyperparameters to ensure fair comparison. This appendix details both model hyperparameters and FSD diagnostic computation parameters.

\subsection*{B.1 NAA-GNN Configuration}

\textbf{Architecture hyperparameters}:
\begin{itemize}
\item Hidden dimension: $d_h = 128$
\item Number of layers: $L = 2$
\item Attention heads: $K = 4$ (concatenation mode)
\item Dropout rate: $p = 0.5$ (applied to all layers)
\end{itemize}

\textbf{NAA-specific parameters}:
\begin{itemize}
\item Numerical similarity weight: $\beta = 0.1$ (initialized, learnable during training)
\item Feature similarity function: $S_{\text{feat}}$ = Log-Cosine (default) or Cosine (for low-dim features)
\item Log-scale base: $b = 10$ for log-magnitude computation
\item Numerical stability constant: $\epsilon = 10^{-8}$
\item Gating activation: sigmoid function
\end{itemize}

\textbf{$S_{\text{feat}}$ selection guideline}:
\begin{itemize}
\item \textbf{Log-Cosine}: For high-dimensional features ($d > 50$) with multi-scale numerical values (financial transactions, bag-of-words). Computes cosine similarity on log-transformed features: $S_{\text{log-cos}}(\mathbf{x}_i, \mathbf{x}_j) = \cos(\log(1+|\mathbf{x}_i|), \log(1+|\mathbf{x}_j|))$
\item \textbf{Standard Cosine}: For low-dimensional features ($d \leq 50$) or normalized features
\item \textbf{NAA-Numerical}: When features span many orders of magnitude (e.g., transaction amounts from \$1 to \$10M)
\end{itemize}

\textbf{Optimization hyperparameters}:
\begin{itemize}
\item Optimizer: Adam with $\beta_1 = 0.9$, $\beta_2 = 0.999$
\item Learning rate: $\alpha = 0.001$
\item Weight decay: $\lambda = 5 \times 10^{-4}$
\item Batch size: full-batch for Elliptic/Amazon; mini-batch (2048) for DGraphFin subgraph
\item Early stopping patience: 50 epochs (monitor validation F1)
\item Maximum epochs: 200
\end{itemize}

\subsection*{B.10 Decision Framework Implementation}

The practical decision framework (Section~\ref{sec:discussion}) uses the following thresholds:

\begin{enumerate}
\item Compute $\rho_{\text{FS}}$ using Algorithm~\ref{alg:fs_alignment}
\item \textbf{If $\rho_{\text{FS}} > 0.15$ AND feature dim $> 50$}: Use NAA (feature-dominant regime)
\item \textbf{If $\rho_{\text{FS}} < -0.05$}: Use H2GCN or MixHop (heterophily regime)
\item \textbf{If $-0.05 \leq \rho_{\text{FS}} \leq 0.15$}: Both approaches viable; consider other factors (class balance, latency)
\item \textbf{If class imbalance $> 100{:}1$}: Prioritize data-level solutions (focal loss, SMOTE, meta-learning)
\end{enumerate}

\textbf{Threshold justification}: The threshold $\rho_{\text{FS}} = 0.15$ was determined empirically as the point where NAA consistently outperforms baselines across our four datasets. The negative threshold $-0.05$ identifies graphs where structural neighbors are systematically feature-dissimilar.
